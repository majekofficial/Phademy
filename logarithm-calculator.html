What a logarithm tells you

A logarithm answers a reverse-power question: what exponent must be applied to a base to produce a given number? If 2³ = 8, then log₂(8) = 3. The base is 2, the number is 8, and the answer is 3. Logarithms are the inverse operation of exponentiation, just as subtraction reverses addition and division reverses multiplication.

Phademy's logarithm calculator asks for a base and a positive number. It returns the logarithm, shows the change-of-base working and provides common, natural and binary logarithms for comparison. When the answer is an exact whole-number power within the tool's checking range, it identifies that exact exponent. Otherwise, it displays a numerical approximation.

Logarithm notation and the definition

The expression log_b(x) = y means bʸ = x. The base b is the number being raised to a power, x is the result, and y is the exponent you are trying to find. For example, log₅(125) = 3 because 5³ = 125. Read the expression as “logarithm of x to base b”.

Every logarithm question can be checked by converting it back into exponential form. If log₃(81) = 4, then 3⁴ must equal 81. This reverse check is a useful way to confirm whether an answer is reasonable. If the result were 3, for example, then 3³ would equal 27, not 81.

How to use the logarithm calculator

Enter the base in the Base field and the positive number in the Number field. For log₂(8), enter 2 as the base and 8 as the number. The result is 3. For log₁₀(100), enter 10 and 100, giving 2. The calculator accepts supported numerical inputs, including fractions such as 1/4.

The base must be positive and cannot equal 1. The number must also be positive. A base of 1 is invalid because 1 raised to any real power remains 1, so it cannot produce a general positive number. A zero or negative number is not accepted as the logarithm's input because the real logarithm is defined only for positive arguments.

Worked example: an exact logarithm

Find log₂(8). Ask what power of 2 gives 8. Since 2 × 2 × 2 = 8, the exponent is 3. Therefore log₂(8) = 3. Check by converting back: 2³ = 8. The calculator identifies this as an exact result.

Other exact examples include log₁₀(1,000) = 3 because 10³ = 1,000, and log₅(125) = 3 because 5³ = 125. Exact integer results are especially easy to verify using exponent rules.

Worked example: a negative logarithm

Find log₂(1/4). The question is: what power of 2 gives one quarter? Since 2² = 4, its reciprocal is 2⁻² = 1/4. Therefore log₂(1/4) = −2. A negative logarithm does not mean that the input is negative. The input is positive but smaller than 1, and the required exponent is negative.

For any base greater than 1, a number between 0 and 1 has a negative logarithm. The logarithm of 1 is zero because every valid base raised to the power zero equals 1. If the base is between 0 and 1, the direction of the relationship changes, so do not assume every positive input below 1 produces the same sign for every possible base.

Worked example: a logarithm that is not a whole number

Find log₃(20). Since 3² = 9 and 3³ = 27, the answer must lie between 2 and 3. Using the change-of-base rule gives log₃(20) = ln(20) ÷ ln(3), which is approximately 2.726833. Check the scale: 3 raised to about 2.7268 is close to 20.

Many logarithms do not have a simple whole-number answer. A calculator uses numerical methods to estimate the exponent. The displayed decimal is an approximation, so a small difference can appear if you raise the base to the rounded answer. Use more precision when a question requires a particular number of decimal places.

The change-of-base formula

The change-of-base formula makes it possible to calculate a logarithm using another logarithm function. It states log_b(x) = log(x) ÷ log(b), where both logarithms on the right use the same base. You can use natural logarithms or common logarithms. For example, log₃(20) = ln(20) ÷ ln(3).

The reason this works is that if bʸ = x, taking the natural logarithm of both sides gives y ln(b) = ln(x). Divide by ln(b) to obtain y = ln(x)/ln(b). The same reasoning works with base-10 logarithms. The important rule is to use the same logarithm base in the numerator and denominator.

Common logarithms and natural logarithms

A common logarithm has base 10 and is often written log(x). A natural logarithm has base e, approximately 2.71828, and is written ln(x). These are two common choices in science and mathematics. The logarithm calculator accepts any valid positive base other than 1, while the scientific calculator provides familiar log and ln functions.

For example, log₁₀(100) = 2 because 10² = 100. The natural logarithm ln(e) = 1 because e¹ = e. Do not confuse log and ln when entering a calculation. A question that specifically asks for a common logarithm normally means base 10; a question that asks for a natural logarithm means base e.

Binary logarithms and powers of two

A binary logarithm has base 2 and is often written log₂(x). It is important in computing because digital information is built from bits, each of which has two possible states. For example, log₂(8) = 3 because three binary choices can represent eight possible combinations. Similarly, log₂(1,024) = 10 because 2¹⁰ = 1,024.

The logarithm of a number does not always need to be a whole number. log₂(1,000) is approximately 9.965784. This tells you that 1,000 is just below 2¹⁰. In practical computing, storing or addressing a fixed number of possibilities may require rounding up to a whole number of bits, but the mathematical logarithm itself can be decimal.

Where logarithms are used

Logarithms are used to solve equations in which the unknown appears as an exponent. If 3ˣ = 20, take logarithms to obtain x = log₃(20), approximately 2.726833. They also appear in exponential growth and decay, where they help calculate how long a process takes to reach a target level.

Some measurement scales are logarithmic because the quantities being compared cover a very wide range. Decibels describe sound intensity ratios on a logarithmic scale. The pH scale is logarithmic and relates to hydrogen ion concentration. The magnitude scales used in earth science also involve logarithmic relationships. In each case, equal steps on the scale correspond to multiplicative changes in the underlying quantity rather than equal additive changes.

Using logarithms to find doubling time

Suppose an amount grows by 5% per period. The growth factor is 1.05, so after n periods the amount is multiplied by 1.05ⁿ. To find when it doubles, solve 1.05ⁿ = 2. Taking logarithms gives n = log(2) ÷ log(1.05), which is approximately 14.2 periods. The answer is not exactly 14 periods; the model predicts the amount first exceeds double after the next whole period if growth occurs only at discrete intervals.

This calculation is an example of why logarithms are useful: they allow you to solve for an exponent. The calculator evaluates the logarithm, but it does not decide whether a particular growth model is realistic. The growth rate, compounding frequency and assumptions must come from the problem you are studying.

Domain restrictions and invalid inputs

The real logarithm of x is defined only when x is greater than zero. There is no real value for log_b(0) or log_b of a negative number. For example, log₂(−8) has no real answer because no real power of a positive base 2 gives a negative result. Complex logarithms exist in advanced mathematics, but they are outside this calculator's purpose.

The base must also be positive and different from 1. A negative base is not allowed in the real logarithm definition used here. A base of 1 is invalid because powers of 1 never move away from 1. The calculator reports an input message rather than returning a misleading numerical answer when these conditions are not met.

Common logarithm mistakes

  • Confusing the base and the number: log₂(8) and log₈(2) are different questions.
  • Mixing log and ln: common log is base 10; natural log is base e.
  • Taking the logarithm of zero or a negative number: these are outside the real domain.
  • Using base 1: it cannot produce a general logarithm result.
  • Adding logarithms incorrectly: log(a + b) is not generally log(a) + log(b).
  • Forgetting the product rule conditions: log(ab) = log(a) + log(b) for positive a and b.
  • Rounding too early: retain precision until the final answer.

Logarithm rules worth remembering

For positive values in the real domain, log_b(xy) = log_b(x) + log_b(y), log_b(x/y) = log_b(x) − log_b(y), and log_b(xⁿ) = n log_b(x). Also, log_b(1) = 0 and log_b(b) = 1 for a valid base. These rules help simplify expressions and solve equations. They do not allow you to split a sum inside a logarithm: log_b(x + y) cannot generally be separated into two logarithms.

Frequently asked questions

What is log base 2 of 8?

It is 3, because 2³ = 8.

What is the logarithm of 1?

It is zero for every valid base, because any positive base other than 1 raised to zero equals 1.

Can a logarithm be negative?

Yes. For a base greater than 1, a positive input between 0 and 1 has a negative logarithm. For example, log₂(1/4) = −2.

Why must the number be positive?

No real power of a positive base produces zero or a negative number. The real logarithm is therefore defined only for positive inputs.

What is the difference between log and ln?

Log commonly means base 10, while ln means the natural logarithm with base e.

How do I calculate a logarithm with a different base?

Use the change-of-base formula: log_b(x) = ln(x) ÷ ln(b), or use the calculator by entering the desired base directly.

How to solve exponential equations with logarithms

Logarithms are especially useful when the unknown appears in an exponent. An equation such as 2ˣ = 20 cannot be solved by ordinary inverse operations such as subtracting 2 or dividing by 2. Instead, take a logarithm of both sides. This gives x log(2) = log(20), so x = log(20)/log(2), approximately 4.321928. The result makes sense because 2⁴ = 16 and 2⁵ = 32, so the required exponent is between 4 and 5.

The base of the logarithm used in the numerator and denominator can be 10 or e, as long as it is the same in both places. This is the change-of-base principle. The logarithm calculator performs this calculation directly when you enter 2 as the base and 20 as the number.

How logarithms compress large ranges

A logarithmic scale is useful when values span many orders of magnitude. On a base-10 scale, moving up by one unit corresponds to multiplying the underlying value by ten. Moving up by two units corresponds to multiplying by one hundred. This is different from a linear scale, where equal steps represent equal additions.

This is why logarithmic scales are used in sound intensity, acidity and some measures of earthquake magnitude. The scale makes a wide range of values easier to compare. However, a difference of one unit on a logarithmic scale does not mean the underlying quantity increased by one ordinary unit. Always check the definition of the scale before interpreting a change.

Understanding the shape of a logarithmic function

For a base greater than 1, the graph of y = log_b(x) increases slowly as x increases. It passes through (1, 0), because log_b(1) = 0, and through (b, 1), because log_b(b) = 1. The graph is only defined for x greater than zero and approaches a vertical boundary near x = 0. It does not cross into negative x-values in the real-number setting.

If the base is between 0 and 1, the graph decreases instead. The domain restriction remains x greater than zero. The calculator accepts any positive base other than 1, so it can calculate values for bases in this range as well. When interpreting the sign or direction of a logarithm, remember to consider whether the base is above or below one.

Use exponential form to check each exact answer. For an approximate answer, raise the base to the displayed exponent and compare it with the original number. A small difference is expected when the exponent has been rounded.

Why logarithm rules need their conditions

The product rule log_b(MN) = log_b(M) + log_b(N) requires M and N to be positive in the real-number setting. The quotient rule requires positive numerator and denominator values. The power rule log_b(M^k) = k log_b(M) also needs attention to the domain, especially when M is negative or the exponent is not an integer. Applying a rule without checking its conditions can create expressions that are not defined in the real numbers.

A common incorrect step is to split log_b(M + N) into log_b(M) + log_b(N). There is no general addition rule of that form. For example, log₁₀(10 + 10) is log₁₀(20), approximately 1.30103, whereas log₁₀(10) + log₁₀(10) equals 2. These values are not equal. The product rule applies to multiplication, not addition.
